## 一、时间分配

### 1.1 每天 3 小时的具体时间表

连续 3 小时做算法题，第 2 小时后效率会明显掉。不要「一口气刷」，按下面的时刻表切块执行。**两个阶段的排法不一样。**

### 1.2 一道题的标准动作（50 分钟）

**原理在动笔之前，不是在写完才搞懂。** 「先写代码 → 能跑通 → 再回头搞懂原理」这个顺序是反的：代码过样例只说明它在这个输入上正确，不说明你的思路对；靠代码反推思路，等于用调出来的结果去猜为什么对，效率极低，而且面试换个数据就崩。

正确顺序：**想清原理（纸上手推小例子）→ 敲代码 → 验证原理（找反例）→ 提炼模板**。中间两步不许碰键盘。

| 步骤 | 时间 | 产出 | 硬性禁止 |
|---|---|---|---|
| ① 读题 | 5 min | 纸上写清：输入是什么、输出是什么、边界条件、返回什么 | 不许看题解、不许碰键盘 |
| ② 想暴力解 | 7 min | 纸上写出暴力解 + 手推一个小例子跑通 | 不许碰键盘 |
| ③ 找瓶颈 | 8 min | 一句话写出「哪里被重复计算了」+ 优化方向 | 不许碰键盘 |
| ④ 编码 | 15 min | 一次写完，不边写边调 | 卡住超 5 分钟就停，回 ③ 改思路 |
| ⑤ 自测 | 5 min | 跑 4 类用例：空 / 单元素 / 重复值 / 负数或极值 | 不许只过示例用例就提交 |
| ⑥ 复盘 | 10 min | 按第五节模板写四行 | 不许拖到晚上补 |

困难题给 70–80 分钟，其余步骤不变。

**判断「原理是否真懂了」的硬标准**：不写代码，能不能用嘴把「这题怎么做、为什么这样做对、换个条件还成不成立」讲清楚。讲不清就别开始敲——敲了也只是在试错。

**写完之后的动作不是「搞懂原理」，而是两件事**：
- **验证**：我的推导对不对？拿极端用例去打它，能打穿说明原理有洞。
- **提炼**：这套思路下次什么特征能触发我想到它？（写进复盘模板第 1 行）

### 1.3 每周节奏

| 时间 | 内容 |
|---|---|
| 周一 ~ 周四 | 每天 2 道新题 + 定时重做 |
| 周五 | 1 道新题 + 本周错题全部重做一遍 |
| 周六（若可投入） | **不碰新题**。整周复盘：整理模板、补做没做出来的题、抽 3 道旧题裸写 |
| 周日 | 休息。看一篇算法科普或干脆不看 |

### 1.4 推进规则（重要）

**按完成度推进，不按日期推进。** 如果某周只来了 4 天，那这一周就顺延，不要压缩内容硬赶进度。计划表里的"第 N 周"指的是"第 N 个学习单元"，不是日历上的第 N 周。

### 第 11 周 · 回溯（8 题）

**回溯的统一骨架**（这周把它背下来）：

```python
def backtrack(路径, 选择列表):
    if 满足结束条件:
        结果.append(路径[:])
        return
    for 选择 in 选择列表:
        if 不合法: continue
        做选择
        backtrack(路径, 新选择列表)
        撤销选择
```

## 五、每题复盘模板

每道题做完，只写这四行，不写长篇大论：

```
【题号】1. 两数之和
【模型】看到"找一对数满足某条件" → 用哈希存 target - x 的下标
【卡点】一开始想用双重循环，没有意识到哈希能把 O(n²) 降到 O(n)
【模板】for i, x in enumerate(nums):
            if target - x in seen: return [seen[target-x], i]
            seen[x] = i
【标记】☑ 独立做出  /  △ 看了提示  /  ✗ 抄了题解
```

复盘文件建议单独建一个 `刷题复盘.md`，按题号顺序追加。

### 卡住时的处理流程（按顺序执行，不要跳步）

1. **硬想 40 分钟**。写出暴力解也算有产出。
2. 40 分钟无思路 → 只读题解的**第一段提示或标题**，关掉页面再想 10 分钟。
3. 还是不行 → 完整看题解，然后**关掉所有页面，从零重写**。
4. 重写不出来 → 抄一遍，但每一行都加注释，说明这行在干什么。
5. 抄完必须能回答三个问题：
   - 为什么这一步是合法的？
   - 如果去掉这一步会怎样？
   - 把题目条件改一下（比如数组变成有重复、要求返回所有解），这解法还成立吗？

**回答不出第 5 步的三个问题 = 这题没学会。** 标记为 ✗，安排 +3 天重做。

## 六、三条红线

| 红线 | 违反的后果 |
|---|---|
| **不按题号刷** | 题号顺序没有教学结构，会反复撞到自己还没学的知识点，一周内必放弃 |
| **不一卡就看题解** | 看懂 ≠ 会写。看题解省下的 30 分钟，会在面试现场用 30 分钟还回来 |
| **不只刷不重做** | 只刷一遍的留存率极低。重做三轮的 100 题，强于只刷一遍的 300 题 |

## 七、时间预期（诚实版）

| 阶段 | 周数 | 累计 |
|---|---|---|
| Python 语法 + 验收 | 2 | 2 周 |
| 哈希 / 双指针 / 滑窗 / 矩阵 | 3 | 5 周 |
| 链表 | 2 | 7 周 |
| 二叉树 | 2 | 9 周 |
| 图 + 栈 + 回溯 | 2 | 11 周 |
| 二分 + 贪心 + DP | 3 | 14 周 |

- 按每周 5 天 × 3 小时执行，**14 周（约 3.5 个月）**可以走完。
- 如果每周只能来 4 天，实际会拉到 **17–18 周**。这不是失败，是正常波动。
- 里程碑判断标准（比"刷完多少题"更可靠）：
  - 第 5 周末：能独立写出双指针和滑动窗口的题，不用查模板
  - 第 9 周末：拿到二叉树题，能 3 分钟内写出递归框架
  - 第 12 周末：看到新题能说出"这属于哪一类、大概什么复杂度"
  - 第 14 周末：随机抽 3 道没做过的中等题，2 道能在 40 分钟内写出可运行且正确的代码

**需要明确的一件事**：刷完 Hot 100 是达到大厂算法面试的入场水平，不是"算法大牛"。大牛的判据是"面对没见过的题也能自己建模并证明正确性"，那需要几千题的积累和对复杂度、正确性证明的熟练。这份计划是起点，不是终点。

## 第 1 周

### 1. 两数之和 · 简单 · 首次 11/16

- **模型**：暴力——「把每一对 (i, j) 都试一遍，看 nums[i] + nums[j] 是否等于 target」。看到「找一对数满足某种关系」→ 枚举所有组合。
- **卡点**：暴力解独立写出，无大卡点。哈希解当天**提前**向 AI 学习了：关键点有二——①要找的数 `target - x` 是确定的，可以边遍历边查，不用每轮重新扫；②必须**先查后存**，否则 `[3,3], 6` 会返回 `[0,0]`（自己配自己）。
- **模板**：
  ```python
  for i in range(len(nums)):
      for j in range(i + 1, len(nums)):
          if nums[i] + nums[j] == target:
              return [i, j]
  ```
- **标记**：☑ 独立（暴力解）｜ 哈希解按 △ 处理 ｜ **W03 哈希周第一件事：裸写 001 哈希版验证，写不出 = 预习作废**
- **重做**：☐ 11/19 ／ ☐ 11/23

### 9. 回文数 · 简单 · 首次 11/16

- **模型**：负数直接 False；正数判断反转后是否相等。两个等价实现：①字符串 `s = str(x); return s == s[::-1]`（最短）；②数字反转 `rev = rev*10 + x%10; x //= 10`（% 取末位，// 删末位）。
- **卡点**：自己首选「转成数字数组」方案，卡在三个机制错误——①`r = len(data)` 起点错，应为 `len(data)-1`（"r 越界"的真凶）；②负数 `int("-")` 直接 ValueError；③for 与 while 混用，for 的步进被 while 内的 `i += 1` 架空。**模型直觉是对的，这就是双指针**（W03 系统学）。最终由 AI 给出 %// 写法完成。原码已存 04-错题本\明细-W01.md。
- **模板**：
  ```python
  # ① 最简：字符串版
  if x < 0:
      return False
  s = str(x)
  return s == s[::-1]

  # ② 半翻转版（进阶，只翻右半，另一种语言里可避免溢出）
  if x < 0 or (x % 10 == 0 and x != 0):
      return False
  rev = 0
  while x > rev:
      rev = rev * 10 + x % 10
      x //= 10
  return x == rev or x == rev // 10      # 偶长度 / 奇长度（中间位不看）
  ```
- **标记**：✗（11/16 AI 给出写法）→ **11/17 D2 裸写一次过，双版本，升为 ☑** ｜ 009 状态：已重做1次
- **重做**：☑ 11/17（一次过）／ ☐ 11/19 ／ ☐ 11/23

### 26. 删除有序数组中的重复项 · 简单 · 首次 11/17

- **模型**：写指针（快慢双指针）——**已排序 → 重复元素必相邻**；s 指向「最后保留的元素」，f 向右扫，`nums[f] != nums[s]` 时先 `s += 1` 再 `nums[s] = nums[f]`。看到「有序 + 原地 + 去重/移除」→ 写指针。
- **卡点**：无，5 分钟一遍过。**诚实备注**：做题前学知识点时看过别的 AI 讲快慢指针，模型来源存疑。但今天任务卡的思路提示本身就给了写指针模型，**今天的及格线是「给定模型 → 自己实现 → 迁移到 27」，不是无提示建模**。真正的检验：11/20 的 +3 重做，以及周六 D6 的变式题。
- **模板**：
  ```python
  s = 0
  for f in range(1, len(nums)):
      if nums[f] != nums[s]:
          s += 1
          nums[s] = nums[f]
  return s + 1
  ```
- **标记**：☑ 独立（5 min，一遍过；模型来源见上）
- **重做**：☐ 11/20 ／ ☐ 11/24

### 27. 移除元素 · 简单 · 首次 11/17

- **模型**：和 26 同一个写指针模板，条件从「和前一个重复」换成「等于 val」。**不变式：f 每一轮都必须 +1**（不管走哪个分支），否则死循环。
- **卡点**：先用「不等→交换」的版本卡住两处——①以为 `s == f` 时需要特判（其实自己换自己是无操作，**不需要**）；②特判的交换代码放错了分支（放在 `nums[f]==val` 的 else 里）。AI 协助定位。最终改用不等判断写对。
- **模板**：
  ```python
  s = 0
  for f in range(len(nums)):
      if nums[f] != val:
          nums[s] = nums[f]     # 覆盖即可，不需要交换
          s += 1
  return s
  # 交换版（nums[s], nums[f] = nums[f], nums[s]）也成立，但 s==f 时是无操作，
  # 不需要特判。交换版真正的用武之地是 283 移动零（要保持非零元素顺序）
  ```
- **标记**：△（思路独立，调试求助 AI）｜ 耗时未报
- **重做**：☐ 11/20 ／ ☐ 11/24

```
【模型】看到"找一对数满足某种和/差关系" → 哈希存"我需要的那个数 → 它的下标"，一趟遍历
【卡点】第一反应是双重循环。没意识到"要找的数是固定的"，所以可以边遍历边查，不用重复扫
【模板】seen = {}
        for i, x in enumerate(nums):
            if target - x in seen: return [seen[target - x], i]
            seen[x] = i
【标记】☑ 独立做出（但暴力解写了 15 分钟，"先想后写"的习惯还没建立）
```

注意「卡点」那一行写的是**思维层面的缺失**（"没意识到要找的数是固定的"），不是"我不会"。这种写法才能在下次遇到同类题时真正起作用。

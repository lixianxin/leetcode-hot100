### 1. 两数之和 · 简单 · 首次 11/16

- **模型**：暴力——「把每一对 (i, j) 都试一遍，看 nums[i] + nums[j] 是否等于 target」。看到「找一对数满足某种关系」→ 枚举所有组合。
- **卡点**：暴力解独立写出，无大卡点。哈希解当天**提前**向 AI 学习了：关键点有二——①要找的数 `target - x` 是确定的，可以边遍历边查，不用每轮重新扫；②必须**先查后存**，否则 `[3,3], 6` 会返回 `[0,0]`（自己配自己）。
- **模板**：
  ```python
  for i in range(len(nums)):
      for j in range(i + 1, len(nums)):
          if nums[i] + nums[j] == target:
              return [i, j]
  ```
- **标记**：☑ 独立（暴力解）｜ 哈希解 △（11/19 重做日凭记忆写哈希版一遍过；`in` 漏写报错 1 次）｜ **W03 验收升级：裸写哈希版 + 口述「先查后存」+ 手推 `[3,3],6`**
- **重做**：☐ 11/19 ／ ☐ 11/23

### 9. 回文数 · 简单 · 首次 11/16

- **模型**：负数直接 False；正数判断反转后是否相等。两个等价实现：①字符串 `s = str(x); return s == s[::-1]`（最短）；②数字反转 `rev = rev*10 + x%10; x //= 10`（% 取末位，// 删末位）。
- **卡点**：自己首选「转成数字数组」方案，卡在三个机制错误——①`r = len(data)` 起点错，应为 `len(data)-1`（"r 越界"的真凶）；②负数 `int("-")` 直接 ValueError；③for 与 while 混用，for 的步进被 while 内的 `i += 1` 架空。**模型直觉是对的，这就是双指针**（W03 系统学）。最终由 AI 给出 %// 写法完成。原码已存 04-错题本\明细-W01.md。
- **模板**：
  ```python
  # ① 最简：字符串版
  if x < 0:
      return False
  s = str(x)
  return s == s[::-1]

  # ② 半翻转版（进阶，只翻右半，另一种语言里可避免溢出）
  if x < 0 or (x % 10 == 0 and x != 0):
      return False
  rev = 0
  while x > rev:
      rev = rev * 10 + x % 10
      x //= 10
  return x == rev or x == rev // 10      # 偶长度 / 奇长度（中间位不看）
  ```
- **标记**：✗（11/16 AI 给出写法）→ **11/17 D2 裸写一次过，双版本，升为 ☑** ｜ 009 状态：已重做1次
- **重做**：☑ 11/17（一次过）／ ☑ 11/19（半翻转版，无卡点）→ **已攻克，11/23 免重做**

### 26. 删除有序数组中的重复项 · 简单 · 首次 11/17

- **模型**：写指针（快慢双指针）——**已排序 → 重复元素必相邻**；s 指向「最后保留的元素」，f 向右扫，`nums[f] != nums[s]` 时先 `s += 1` 再 `nums[s] = nums[f]`。看到「有序 + 原地 + 去重/移除」→ 写指针。
- **卡点**：无，5 分钟一遍过。**诚实备注**：做题前学知识点时看过别的 AI 讲快慢指针，模型来源存疑。但今天任务卡的思路提示本身就给了写指针模型，**今天的及格线是「给定模型 → 自己实现 → 迁移到 27」，不是无提示建模**。真正的检验：11/20 的 +3 重做，以及周六 D6 的变式题。
- **模板**：
  ```python
  s = 0
  for f in range(1, len(nums)):
      if nums[f] != nums[s]:
          s += 1
          nums[s] = nums[f]
  return s + 1
  ```
- **标记**：☑ 独立（5 min，一遍过；模型来源见上）｜ **裸写（11/17）：通过，且从 for 换成了 while 手动步进——s 指向最后保留元素、比较 nums[s]/nums[f] 的变体也能写对**
- **重做**：☐ 11/20 ／ ☐ 11/24

### 27. 移除元素 · 简单 · 首次 11/17

- **模型**：和 26 同一个写指针模板，条件从「和前一个重复」换成「等于 val」。**不变式：f 每一轮都必须 +1**（不管走哪个分支），否则死循环。
- **卡点**：先用「不等→交换」的版本卡住两处——①以为 `s == f` 时需要特判（其实自己换自己是无操作，**不需要**）；②特判的交换代码放错了分支（放在 `nums[f]==val` 的 else 里）。AI 协助定位。最终改用不等判断写对。
- **模板**：
  ```python
  s = 0
  for f in range(len(nums)):
      if nums[f] != val:
          nums[s] = nums[f]     # 覆盖即可，不需要交换
          s += 1
  return s
  # 交换版（nums[s], nums[f] = nums[f], nums[s]）也成立，但 s==f 时是无操作，
  # 不需要特判。交换版真正的用武之地是 283 移动零（要保持非零元素顺序）
  ```
- **标记**：△（思路独立，调试求助 AI）｜ **裸写（11/17）：通过。上一轮「死循环」争议已定案：提交版 f+=1 位置正确，小算按丢失缩进的文本误读，判错纠正**
- **重做**：☐ 11/20 ／ ☐ 11/24

### 66. 加一 · 简单 · 首次 11/18

- **模型**：从后往前遍历——加 1 只作用在个位上，只有进位才往左走。末位非 9 → +1 直接结束；是 9 → 变 0 继续往前；全部走完还是 9 → 头部插 1。看到「数字 +1 / 进位」→ 从末位往前扫。
- **卡点**：思路对（草稿推了全 9），代码三处错：①`range(-1, -len(digits), -1)` **不含最高位** `-len`（即下标 0），任何进位链走到最高位都漏——不止全 9，`[1,9,9]` 也会原样返回；②置 0 内层 `range(-i, 0, -1)` 正负下标混用，`[1,2,9]` 会把刚 +1 的那一位清成 0；③全 9 无 `[1]+[0]*n` 分支。13 min 没写对 → 问 AI + 看题解后 9 min 写出。
- **模板**（任务卡版，比题解版**少一个内层循环**，推荐用这个）：
  ```python
  for i in range(len(digits) - 1, -1, -1):
      if digits[i] != 9:
          digits[i] += 1
          return digits          # 不进位，直接收工
      digits[i] = 0              # 是 9 就变 0，继续往前
  digits.insert(0, 1)            # 走完全部还是 9 → 头部补 1
  return digits
  ```
- **标记**：✗（问 AI + 看题解后写出）｜ 耗时 13 + 9 min ｜ 裸写（当日，看题解后约 30 min）：通过（题解版②）——短时记忆，✗ 不撤销
- **重做**：△ 11/19（版①补测**看了写法才写，不算盲写**；口述结构正确）→ **版① 正式盲写：11/21 D6** ／ ☐ 11/25

### 58. 最后一个单词的长度 · 简单 · 首次 11/18

- **模型**：`s.split()`（**不带参数**，自动合并连续空格、去首尾）→ 单词列表 → 取 `[-1]` 求 `len`。看到「按空白切单词」→ `split()` 不带参数。
- **卡点**：思路和主体代码独立写出（约 3 min），但防御判断写成 `if data is None`——`split()` **永远返回 list（可能为空），绝不返回 None**，这个判断永远 False，是死代码；一旦输入可能全空格，`data[-1]` 照样 IndexError。AI 纠正为 `if not data`。
- **模板**：
  ```python
  words = s.split()      # 不带参数！
  if not words:          # 空 list 是 False；is None 永远不成立
      return 0
  return len(words[-1])
  ```
- **标记**：△（思路独立，语法求助 AI）｜ 耗时约 3 min + 修正
- **重做**：☐ 11/21 ／ ☐ 11/25

### 14. 最长公共前缀 · 简单 · 首次 11/19

- **模型**：公共前缀是**按位置逐位比较**——纵向扫描（以 strs[0] 为基准，第 i 位问所有串"你这个位置的字符和我一样吗"）或横向扫描（两两求公共前缀再收缩）。看到「所有串的最长 XX」→ 选基准 + 逐位验证。
- **卡点**：**思路模型错**——用 set 交集求公共字符。set 是无序的"成员资格"，前缀是有序的"位置相等"：`["abc","cba"]` 的 set 交集是 `{a,b,c}`，但公共前缀是 `""`。另踩三个语法坑：①`str` 当变量名遮蔽内置类型；②`for str in enumerate(strs)` 拿到的是 (下标, 串) 元组；③`split(:len(max))` 应为切片 `[:k]`——取前 k 个字符是切片不是 split。看题解 + 纵向版后理解。
- **模板**（纵向版）：
  ```python
  first = strs[0]
  for i in range(len(first)):
      ch = first[i]
      for s in strs[1:]:
          if i >= len(s) or s[i] != ch:   # 先判越界再取值
              return first[:i]
  return first
  ```
- **标记**：✗（思路错 + 看题解）｜ **裸写（11/19）：通过**——防越界写成 `i+1 > len(s)`，与 `i >= len(s)` 数学等价；自评「靠记忆写的」，待答口述「为什么是 return pre[:i]」
- **重做**：☐ 11/22（D6）／ ☐ 11/26

### 13. 罗马数字转整数 · 简单 · 首次 11/19

- **模型**：从左往右扫，每一位和下一位比：`s[i] < s[i+1]` → 减 `s[i]`；否则加 `s[i]`。最后一位没有下一位，天然落 else。
- **卡点**：**模型自己想对了**（和标准解一致）——这题的难处本来就在建模，你已经过了一半。实现卡两点：①`i + 1 < len(s)` 越界前置不会落码；②dict 建表取值不熟。清单里直接放了完整骨架（小算流程问题，已修正：以后骨架只给结构不给答案），照抄通过。
- **模板**：
  ```python
  vals = {'I': 1, 'V': 5, 'X': 10, 'L': 50, 'C': 100, 'D': 500, 'M': 1000}
  total = 0
  for i in range(len(s)):
      if i + 1 < len(s) and vals[s[i]] < vals[s[i + 1]]:   # 越界判断写在取值前面
          total -= vals[s[i]]
      else:
          total += vals[s[i]]
  return total
  ```
- **标记**：✗（看现成代码后写出；模型 △，实现 ✗）｜ **裸写（11/19）：通过**；口述亮点：自问「V 在 X 前会不会乱减」→ 结论：算法依赖**输入合法**前提（合法罗马数字中 V/L/D 永不作减前缀）
- **重做**：☐ 11/22 ／ ☐ 11/26

### 217. 存在重复元素 · 简单 · 首次 11/20

- **模型**：看「有没有重复」→ 全塞进 set（集合自动去重），最后长度变短 = 有重复。复杂度：时间 O(n) 期望（`set.add` 平均 O(1)），空间 O(n)。
- **卡点**：无大卡点，5 min。自省「遍历的 i 没用上」**正确**——`enumerate` 给的 i 用不到就别要，写 `for num in nums`。另有一个一行版：先整体去重再比长度。
- **模板**：
  ```python
  s = set()
  for num in nums:
      s.add(num)
  return len(s) < len(nums)
  # 一行版：return len(set(nums)) < len(nums)
  # 进阶（W03）：add 之后 len(s) 不增 = 发现重复，可提前 return True，不用扫完全部
  ```
- **标记**：☑ 独立（5 min）｜ 裸写：☐（11:00 块）
- **重做**：☐ 11/23 ／ ☐ 11/27

### 242. 有效的字母异位词 · 简单 · 首次 11/20

- **模型**：字符计数——两串中每种字符出现次数完全一致 → 异位词。dict 计数后逐 key 对数。复杂度：时间 O(n)，空间 O(1)（小写字母最多 26 个 key，与 n 无关）。
- **卡点**：初版漏「长度不等直接 False」，提交时卡住后**自己补上**。这个检查不是可选项：没有它，`s="a"`、`t="ab"` 时最终循环只验证「s 的每种字符在 t 里够不够」，**t 里多出来的字符根本查不到**，会错判 True。这和 009 的「先存后查」同类：**比较逻辑只覆盖一边时，长度兜底就是唯一防线**。
- **模板**：
  ```python
  if len(s) != len(t):        # 兜底：t 多出来的字符，下面的比较查不到
      return False
  c1, c2 = {}, {}
  for ch in s:
      c1[ch] = c1.get(ch, 0) + 1   # get(k, 0) 可替掉 if/else 计数
  for ch in t:
      c2[ch] = c2.get(ch, 0) + 1
  return c1 == c2                  # dict 直接相等比较，可替掉逐 key 循环
  # 版②（了解）：单 dict 加减法——s 加 1 t 减 1，最后检查全 0；
  #   或一行：return collections.Counter(s) == Counter(t)
  ```
- **标记**：☑ 独立（长度检查提交时卡一下，自行补上）｜ 裸写：☐（11:00 块）
- **重做**：☐ 11/23 ／ ☐ 11/27

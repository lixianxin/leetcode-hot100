### 009. 回文数 · 简单 · W01-D1

> 注：以下代码是**按用户描述还原的卡点形态**，不是原样代码。D2 汇报时把卡住时的代码贴出来，替换进「我的错误代码」一栏。

**我的错误代码（还原）**

```python
# 思路：把 x 转成数字数组，再比较
digits = []
t = x
while t > 0:                 # ← x = 0 时循环一次都不执行，digits = []，后面取元素炸
    digits.append(t % 10)
    t //= 10
# 之后用下标比较 digits[i] 和 digits[-1-i]，数组为空时 IndexError（"r 越界"）
```

**错在哪**

三个边界，全在数组方案上：
1. **x = 0**：`while t > 0` 一次都不进，`digits` 为空，取 `digits[0]` 越界 → IndexError
2. **x < 0**：负号不是数字，转不成数字数组，也没单独处理
3. **下标越界**：一边遍历一边（可能）改动数组长度，访问位置超过了 `len - 1`

**正确写法（两个等价，都背下来）**

```python
# ① 字符串版（最短，推荐）
if x < 0:
    return False
s = str(x)
return s == s[::-1]

# ② 数字反转版（AI 给出的：% 取末位，// 删末位）
if x < 0:
    return False
rev, t = 0, x
while t:
    rev = rev * 10 + t % 10   # 取出末位，接到反转数的尾部
    t //= 10                   # 删掉末位
return rev == x
```

**为什么**

- 数组方案的本质问题是**多了"建数组 + 管下标"两个环节**，每个环节都自带边界；数字反转不建任何中间结构，`while t` 天然处理 0（循环不进，rev=0，0==0 成立）。
- `% 10` 取末位、`// 10` 删末位，是"从右往左逐位处理一个整数"的通用套路，66 加一、231 2 的幂都会再用到。

**一句话教训**

取数组元素之前先问自己一句「**这个数组此刻一定非空吗**」；能用一次遍历直接算出答案的，不要先建中间数组——中间结构每多一个，边界就多一批。

### 001. 两数之和 · 简单 · W01-D1（示例）

**我的错误代码**

```python
seen = {}
for i, x in enumerate(nums):
    seen[x] = i                  # ← 错在这里：先把当前元素存进去
    if target - x in seen:
        return [i, seen[target - x]]
```

**错在哪**

第 3 行写入，第 4 行才查询。对 `nums = [3,3], target = 6`：
- `i=0`：先把 `3` 存进 `seen`，紧接着查 `need = 3`，命中的是**自己**刚存的那条，返回 `[0,0]`
- 同一元素被用了两次，违反题面"同一元素不能重复使用"

**正确写法**

```python
seen = {}
for i, x in enumerate(nums):
    need = target - x
    if need in seen:             # ← 先查
        return [seen[need], i]
    seen[x] = i                  # ← 后存
```

**为什么**

查询和写入的**顺序**不是风格问题，是被"元素不能重复使用"这个约束逼出来的。先存 = 允许自己和自己配对；先查 = 只允许和之前出现过的数配对。

**一句话教训**

凡是"不能重复使用同一元素"的题，都要检查**查询与写入的先后**；写完示例用例过了不代表对，要专门造一个"重复值"用例去打它。

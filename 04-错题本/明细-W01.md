### 009. 回文数 · 简单 · W01-D1

**我的错误代码（原样保留，2026-11-16 D1）**

```python
class Solution:
    def isPalindrome(self, x: int) -> bool:
        data = list(int(num) for num in str(x))
        medim = int(len(data) / 2) + 1
        r = len(data)
        for i in range(len(data)):
            while i < medim:
                if data[i] == data[r]:
                    i += 1
                    r -= 1
                else:
                    return False
        return True
```

**错在哪（三处，按严重度）**

1. **第 4 行 `r = len(data)` —— 直接越界，这是"r 越界"的真正来源**。`data` 合法下标是 `0 ~ len-1`，`data[r]` 第一次比较就访问 `data[len(data)]`，对任何输入（包括 121）都当场 `IndexError`。应从 `r = len(data) - 1` 开始。
2. **负数没处理，且比想的更早炸**：`str(-121)` 得到 `"-121"`，逐字符 `int("-")` 直接 `ValueError`——连进循环的机会都没有。必须在最前面 `if x < 0: return False`。
3. **for 和 while 混用（用户自己已诊断出）**：`for i in range(...)` 里的 `while i < medim` 自己推进 `i`，for 的步进完全没参与；while 结束后 for 继续拿下一个 `i` 进来，`r` 却是上一轮剩下的旧值，导致比较错乱。**一个循环该干的事只用一种循环干**。

**正确写法（三个版本，按推荐排序）**

```python
# ① 字符串版（最短，D2 裸写默认写这个）
if x < 0:
    return False
s = str(x)
return s == s[::-1]

# ② 数字反转版（% 取末位，// 删末位）
if x < 0:
    return False
rev, t = 0, x
while t:
    rev = rev * 10 + t % 10
    t //= 10
return rev == x

# ③ 你的"数字数组"思路修复版 —— 你的直觉其实是对的，
#    这就是标准"双指针"写法，W03 会正式学
if x < 0:
    return False
data = [int(c) for c in str(x)]
l, r = 0, len(data) - 1        # ← 唯一关键修复：r 从 len-1 开始
while l < r:                   # ← 一个 while 干完所有事，不要 for
    if data[l] != data[r]:
        return False
    l += 1
    r -= 1
return True                    # ← x=0 时 data=[0]，l==r 不进循环，天然返回 True
```

**为什么**

你的思路（拆成数字数组、两头往中间比）没有错，错的全是机制：下标起点、负数预处理、两种循环混用。修复版只改三处，逻辑立刻通。这说明你的**模型直觉是好的**——这个"两头往中间收"的结构就是双指针，W03 会系统学。

**一句话教训**

数组合法下标是 `0 ~ len-1`，**从右端开始比较时起点永远是 `len - 1`，不是 `len`**；写完先拿最小输入（0、单元素）手推一遍下标走向，越界在纸上就能发现，不用等 Python 报错。

**正确写法（两个等价，都背下来）**

```python
# ① 字符串版（最短，推荐）
if x < 0:
    return False
s = str(x)
return s == s[::-1]

# ② 数字反转版（AI 给出的：% 取末位，// 删末位）
if x < 0:
    return False
rev, t = 0, x
while t:
    rev = rev * 10 + t % 10   # 取出末位，接到反转数的尾部
    t //= 10                   # 删掉末位
return rev == x
```

**为什么**

- 数组方案的本质问题是**多了"建数组 + 管下标"两个环节**，每个环节都自带边界；数字反转不建任何中间结构，`while t` 天然处理 0（循环不进，rev=0，0==0 成立）。
- `% 10` 取末位、`// 10` 删末位，是"从右往左逐位处理一个整数"的通用套路，66 加一、231 2 的幂都会再用到。

**一句话教训**

取数组元素之前先问自己一句「**这个数组此刻一定非空吗**」；能用一次遍历直接算出答案的，不要先建中间数组——中间结构每多一个，边界就多一批。

### 066. 加一 · 简单 · W01-D3

**我的错误代码（原样保留，2026-11-18 D3，13 min 未写对）**

```python
class Solution:
    def plusOne(self, digits: list[int]) -> list[int]:
        if digits[-1] != 9:
            digits[-1] = digits[-1] + 1
        else:
            for i in range(-1, -len(digits), -1):
                if digits[i] != 9:
                    digits[i] = digits[i] + 1
                    for j in range(-i, 0, -1):
                        digits[j] = 0
                    break
            return digits
        return digits
```

**错在哪（三处，全部能定位到行）**

1. **第 5 行 `range(-1, -len(digits), -1)` 不含最高位**。含左不含右对倒序同样成立：循环到 `-len(digits)+1` 就停，**下标 0（最高位）永远不会被检查**。所以错的远不止全 9——任何进位链走到最高位都漏：`[1,9,9]` 会原样返回 `[1,9,9]`（应为 `[2,0,0]`），`[9,9]` 返回 `[9,9]`。若想包含下标 0，右边界必须写 **-1**（`range(-1, -len(digits)-1, -1)`）。
2. **第 8 行内层 `for j in range(-i, 0, -1)` 正负下标混用**。`i` 是负下标，`-i` 变成正数，`j` 却拿去当正下标用。手推 `[1,2,9]`：`i=-2` 时 `digits[-2]` 加成 3，接着 `j` 取 2、1 → `digits[2]=0, digits[1]=0` → **把刚 +1 的那一位也清掉了**，输出 `[1,0,0]`（应为 `[1,3,0]`）。
3. **全 9 无 `[1]+[0]*n` 分支**——草稿里推到了，代码里没落。**草稿考虑的分支，编码时必须逐条落到代码里，少一条就是漏分支**（用户自己诊断出了这条）。

**正确写法（两个版本，推荐 ①）**

```python
# ① 任务卡版（推荐）：边走边把 9 置 0，不需要任何内层循环
for i in range(len(digits) - 1, -1, -1):
    if digits[i] != 9:
        digits[i] += 1
        return digits          # 不进位，直接收工
    digits[i] = 0              # 是 9 就变 0，继续往前
digits.insert(0, 1)            # 走完全部还是 9 → 头部补 1
return digits

# ② 题解版（你抄的）：遇到非 9 后回头把后面清零，多一个内层循环，
#    逻辑也对，但你抱怨的"步骤多、下标不好写"正是这个设计带来的
n = len(digits)
for i in range(n - 1, -1, -1):
    if digits[i] != 9:
        digits[i] += 1
        for j in range(i + 1, n):
            digits[j] = 0
        return digits
return [1] + [0] * n
```

**为什么 ① 更简单**

① 的洞察：走的过程中遇到的 9 **当场就置 0**，不需要回头补。② 的洞察：遇到非 9 就停止，后面一次性清零。两种都对，但 ① 只有一个循环、一套下标——你原代码的复杂度（外层负下标 + 内层正下标 + break）正是"步骤多所以下标乱"的根源。**当一段代码让你觉得"下标不好写"，通常不是你下标学得差，是设计绕了，先回头简化设计再写。**

**一句话教训**

倒序 range 的右边界是 **-1 不是 -len**（想包含下标 0）；刷题默认正下标（`range(len-1, -1, -1)`），负下标只用于快速取尾（`digits[-1]`）和切片——正负下标混用是下标 bug 的头号来源。

### 058. 最后一个单词的长度 · 简单 · W01-D3

**我的错误代码（原样保留）**

```python
data = s.split()
if data is None:
    return 0
return len(data[-1])
```

**错在哪**

第 2 行：`split()` **永远返回 list（可能为空），绝不返回 None**，所以 `data is None` 永远 False——这个判断是死代码。它最危险的地方是给你"已经防御过了"的错觉：一旦输入全空格，`data = []`，跳过判断，`data[-1]` 直接 IndexError。（本题 LeetCode 保证至少一个单词，所以提交能过——**碰巧对，不是想对了**，和 009 的「先存后查」过示例是同一类陷阱。）

**正确写法**

```python
words = s.split()
if not words:          # 空 list 是 False
    return 0
return len(words[-1])
```

**为什么**

Python 真值规则：空 list / 空 str / 空 dict / 0 / None 全是 False。判断"容器是否为空"用 `if not data`；`is None` 只用于变量**真的可能被赋成 None** 的场景（比如函数没写 return 时返回值就是 None）。

**一句话教训**

判断容器为空用 `if not data`，`is None` 永远别用来判空——它判的是"变量本身是 None"，而 `split()`、切片、遍历都不会返回 None。

### 080. 删除有序数组中的重复项 II（26 的变式）· 中等 · W01-D6（11/23）

**我的错误代码**

```python
s = 1
f = 2
for i in range(1, len(nums)):
    if f < len(nums) and (nums[i] != nums[f] or nums[i - 1] != nums[f]):
        s += 1
        nums[s] = nums[f]
    f += 1
return s + 1
```

**错在哪（三处，按严重度）**

1. **模型错（根因）：规则变了，不变式没跟着变。** 26 的不变式是「s 指向最后一个保留元素，候选和它不同就收」。这题允许保留两个，**光知道「上一个保留的值」不够了，必须知道「上上个保留的值」**——候选只有和 s 前面第二个保留元素也不同，才可能是第三次出现之前的合法新值。这个信息用下标表达就是 `nums[s-2]`。清单里第 3 个提示问的就是这个（"需要知道什么信息？能不能用一个下标表达？"），没接上。
2. **设计错：两个读指针 i、f 干同一件事。** `for i` 已经在从左往右扫，f 又手动从 2 起步再自增——i 和 f 永远错位 1，条件里 `nums[i]` 和 `nums[f]` 比的是**两个候选位置**，谁都不是「保留区」，比较无意义。而且 f 从 2 起步，`nums[1]` 作为候选被直接跳过，`[1,1,1]` 这类输入从第一轮就漏判。
3. **边界错：`return s + 1`。** 这题 s 若从「已保留个数」语义起步就该返回 s；s+1 是 26 的返回习惯（s 是下标），两题语义不同不能照搬。**返回值前先问自己：s 现在是下标还是个数？**

**为什么卡**：26 的模板是「记一个值就够」（保留区的最后一个），80 需要「记两个值」。当模板的前提被破坏时，正确动作是**回到纸上重新推不变式**，而不是套着旧形状改条件——你 13 分钟都在改条件，没退回第②步。

**一句话教训**

题目条件每变一点，先重写循环不变式（s 指向什么、写入前要比较什么），再动代码；模板是出发点，不是终点。

### 001. 两数之和 · 简单 · W01-D1（示例）

**我的错误代码**

```python
seen = {}
for i, x in enumerate(nums):
    seen[x] = i                  # ← 错在这里：先把当前元素存进去
    if target - x in seen:
        return [i, seen[target - x]]
```

**错在哪**

第 3 行写入，第 4 行才查询。对 `nums = [3,3], target = 6`：
- `i=0`：先把 `3` 存进 `seen`，紧接着查 `need = 3`，命中的是**自己**刚存的那条，返回 `[0,0]`
- 同一元素被用了两次，违反题面"同一元素不能重复使用"

**正确写法**

```python
seen = {}
for i, x in enumerate(nums):
    need = target - x
    if need in seen:             # ← 先查
        return [seen[need], i]
    seen[x] = i                  # ← 后存
```

**为什么**

查询和写入的**顺序**不是风格问题，是被"元素不能重复使用"这个约束逼出来的。先存 = 允许自己和自己配对；先查 = 只允许和之前出现过的数配对。

**一句话教训**

凡是"不能重复使用同一元素"的题，都要检查**查询与写入的先后**；写完示例用例过了不代表对，要专门造一个"重复值"用例去打它。

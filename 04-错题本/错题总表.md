## 使用规则

**什么算错题**（四种都要进，别只记"没做出来"的）：

| 类型 | 判定 | 严重度 |
|---|---|---|
| A 完全不会 | 40 分钟无思路 | 高 |
| B 思路对写不出 | 知道怎么做，代码卡住 | 中 |
| C 写出来但错用例 | 提交被拒，或自测用例挂 | 高（最危险，说明原理有洞） |
| D 写对但复杂度过高 | 通过但超时/超内存，或自己判断是暴力解 | 中 |

**C 类必须重点记**——因为它最容易被"示例通过了"掩盖。

**进表的动作**：
1. 在下面总表加一行
2. 在同周 `明细-WNN.md` 写详细：**当时的错误代码（原样保留）** → 错在哪一行 → 正确写法 → 一句话教训
3. 如果在 `高频复发` 里出现（错≥2 次），触发专项攻坚

**状态取值**：待重做 / 已重做1次 / 已重做2次 / 已攻克（连续两次裸写通过）

**错因分类**（统一用这 7 类，方便统计你的薄弱点）：

| 代码 | 分类 | 典型表现 |
|---|---|---|
| `语法` | Python 语法不熟 | 切片写错、`range` 边界、缩进、类型转换 |
| `边界` | 边界条件漏 | 空数组、单元素、全相同、越界、负数 |
| `题意` | 题意理解偏 | 返回长度写成返回数组、原地改写成新建 |
| `模型` | 想不到模型 | 该用哈希用了暴力、该用双指针用了嵌套循环 |
| `复杂` | 复杂度判断错 | 循环里调 `list.count()`、字符串拼接 O(n²) |
| `模板` | 模板记混 | 二分左右边界混、回溯忘撤销 |
| `调试` | 调试方法问题 | 边写边改、只跑示例用例 |

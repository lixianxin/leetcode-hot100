## 1. 变量与类型（D1）

```python
a = 3          # 整数 int
s = "abc"      # 字符串 str
f = 1.5        # 浮点 float
b = True       # 布尔 bool

print(a, s)            # 3 abc
print(f"{a} 和 {s}")   # 3 和 abc     ← f-string，调试时最常用
```

**三种类型转换**

```python
int("3")     # → 3
str(3)       # → "3"
int(3.9)     # → 3    ← 直接截断，不是四舍五入
```

**坑**：`"3" + 3` 会报 `TypeError`。字符串和数字不能直接相加，必须先转。

**判断类型**

```python
type(a)                  # <class 'int'>
isinstance(a, int)       # True
```

### 为什么不用写 int a（和 Java 的根本区别）

```python
a = 3        # a 指向 3
a = "abc"    # 合法！a 改指向 "abc"，类型跟着变
```

Java 的 `int a = 3;` 是「开一个只能装 int 的盒子，把 3 放进去」——**盒子的类型锁死**，装字符串会编译报错。

Python 的 `a = 3` 是「给 3 贴一张叫 a 的标签」——**标签可以随时撕下来贴到别的东西上**，所以类型不固定。

这带来三个实际后果，做题时会遇到：

| 后果 | 具体表现 |
|---|---|
| 不用声明类型 | 省事，但看代码时要靠上下文判断 a 现在是什么 |
| 同一变量可换类型 | `a = 3` 再 `a = "abc"` 不报错。**代价是 bug 更隐蔽** |
| 类型错误在运行时才暴露 | `"3" + 3` 会跑到那一行才炸；Java 是编译期就拦住 |

所以读 Python 报错时不要慌：**报错的那一行，往往不是写错的那一行**。比如 `TypeError` 常常是因为上一行某个变量被赋成了另一种类型。

## 2. 字符串操作（D1、D3、D5）

```python
s = "Hello"
len(s)          # 5
s[0]            # "H"      ← 索引从 0 开始
s[-1]           # "o"      ← -1 表示最后一个
s[1:3]          # "el"     ← 切片，含左不含右
s[:2]           # "He"
s[2:]           # "llo"
s[::-1]         # "olleH"  ← 反转，步长 -1

s.lower()       # "hello"
s.upper()       # "HELLO"
s.split()       # 按空白切分
```

### split 的两个版本（D3 会踩坑）

```python
"  a  b  ".split()      # ["a", "b"]          ← 不带参数：自动合并连续空格、去掉首尾空格
"  a  b  ".split(" ")   # ["", "", "a", "", "b", "", ""]   ← 带参数：一个空格都不放过
```

**结论：刷题时几乎总是用 `s.split()`，不要带参数。** 58 题就是在这里翻车的。

## 3. list 与原地修改（D2）

```python
a = [1, 2, 3]
len(a)          # 3
a[0]            # 1
a[-1]           # 3
a[0] = 9        # 改：a 变成 [9, 2, 3]

a.append(4)     # 尾部加：  [9, 2, 3, 4]
a.pop()         # 弹出尾部： 返回 4
a.insert(0, 7)  # 头部插入：[7, 9, 2, 3]   ← 注意这是 O(n)，所有元素要往后挪
```

**遍历的两种写法**

```python
for x in a:                      # 只要值
    print(x)

for i in range(len(a)):          # 要下标（因为要改 a[i]）
    a[i] = a[i] * 2
```

### "原地修改"是什么意思（D2 的核心）

题目说「**原地**删除/修改」，意思是：**不许新建一个数组返回，只能改原来那个数组**。

所以 26 题不能写：

```python
return list(set(nums))        # ✗ 这是新建了一个数组，原数组没动
```

必须写成：

```python
# 在原数组上，把不重复的元素往前挪
k = 1
for i in range(1, len(nums)):
    if nums[i] != nums[k-1]:
        nums[k] = nums[i]
        k += 1
return k                      # ✓ 返回长度 k，nums[:k] 就是结果
```

**为什么返回值是 k 而不是数组**：判题程序会检查 `nums[:k]` 的内容。你返回 k，它自己去看数组前 k 个对不对。

## 4. 循环与 range（D3）

```python
range(3)                 # 0, 1, 2          ← 不含 3！
range(1, 4)              # 1, 2, 3          ← 含左不含右
range(0, 5, 2)           # 0, 2, 4          ← 第三个参数是步长
range(4, -1, -1)         # 4, 3, 2, 1, 0    ← 倒序！三步参数缺一不可
```

`range(4, -1, -1)` 是 66 加一题的关键。三个参数分别读作：**从 4 开始，到 -1 之前停（即到 0），每次减 1**。

```python
while i < n:
    ...
    i += 1

for x in a:
    if x == 0:
        break            # 立刻跳出整个循环
    if x < 0:
        continue         # 跳过本次，进入下一轮
```

### 4.1 什么时候才需要下标（11/28 · 383 答疑沉淀）

> 触发：383 用 `for i in range(len(...))` 遍历，首版把 `i` 拿去索引了**另一个**字符串（`hashmap[magazine[i]] -= 1`），造成「下标张冠李戴」。两版复杂度相同，差别只在**这类 bug 有没有发生的可能**。

**Java 迁移提醒**：`for (int i = 0; i < n; i++) { a[i] }` 是肌肉记忆，但 Python 的 `for` 是 **for-each**——直接把元素交给你，不需要中间下标。写成 `range(len())` 等于自己重新造了个 `i`，而 `i` 只是个裸整数，**不携带「我属于哪个序列」的信息**，所以可以被拿去索引任何序列。

| | 下标式 | for-each |
|---|---|---|
| 写法 | `for i in range(len(s)): s[i]` | `for ch in s: ch` |
| 拿到的是 | 位置（还要回查一次） | 元素本身 |
| 循环里有两个序列时 | `i` 可能串到另一个序列 → **bug 入口** | 没有下标，串不了 |
| 383 结果 | 修正后正确（225 组对拍 0 不一致） | 正确 |

**判据：只有这 4 种情况才用下标**

1. 要**返回下标**（387 第一个唯一字符、001 两数之和）
2. 要**原地写入某个位置**（027/080 的 `nums[s]`、88 的 `nums1[p]`、344 的 `s[i], s[j]` 互换）
3. 要**对齐多个序列的同一位置**（014 纵向扫描 `str1[i] != s[i]`、88 三指针）
4. 要**比较相邻元素**（013 的 `s[i]` vs `s[i+1]`）

除此之外一律 `for ch in s`。同时要下标和元素时用 `enumerate(s)`（第 5 节）。

**落码前三句自问**（一旦用了 `i` 就必须答）：`i` 是谁产生的？我拿它索引的是谁？这两个是同一个序列吗？

**配套：`get(k, 0)` 不只用于建表**

```python
d[k] = d.get(k, 0) + 1     # 建表侧：key 不存在时垫 0，免 KeyError
if d.get(ch, 0) <= 0: ...  # 查询侧：把「不存在」和「用完了」合并成一个条件
```

下标版写的是 `if ch not in d or d[ch] == 0`——两个条件靠 `or` **短路**保护（顺序反了就 KeyError），和 013 的 `i+1 < len(s) and ...`、014 的 `i >= len(s) or ...` 是同一个套路。`get(ch, 0) <= 0` 用一个数值条件代替，少一层短路依赖。**`<= 0` 也比 `== 0` 更贴题意**：本题二者等价（计数永不为负），但「不够就失败」的语义用 `<= 0` 表达更准。

**一句话**：for-each 版不是更快的写法（两版都是 O(m+n) 时间 / O(1) 空间），是**把「下标张冠李戴」这类 bug 的发生条件删掉了**的写法。

## 5. dict 与 set（D5，全课程最重要的一节）

```python
d = {}                       # 空字典
d["a"] = 1                   # 写入
d["a"]                       # 读取 → 1；键不存在会 KeyError
"a" in d                     # 判断存在 → True
d.get("b", 0)                # 安全读取 → 0（不存在时返回默认值，不报错）
for k, v in d.items():       # 同时遍历键和值
    print(k, v)
```

```python
s = set()                    # 空集合（不能写 s = {}，那是空字典！）
s.add(1)
1 in s                       # True
len(set([1,2,2,3]))          # 3
```

### 这一节唯一必须记住的结论

| 操作 | 数据结构 | 时间复杂度 |
|---|---|---|
| `x in a` | list | **O(n)** ← 从头扫一遍 |
| `x in d` | dict | **O(1)** ← 直接定位 |
| `x in s` | set | **O(1)** |

**为什么重要**：217 题如果你在循环里用 `nums.count(x)`，那是 O(n) 套 O(n) = O(n²)。用 set 就是 O(n)。**后面 90 道题的优化，一大半是在做这个替换。**

### enumerate

```python
for i, x in enumerate(["a", "b"]):
    print(i, x)      # 0 a  /  1 b
```

比 `for i in range(len(a)): a[i]` 更干净，能用就用。

## 6. 函数（D4）

```python
def add(a, b):
    return a + b

def find(nums, target):
    for i, x in enumerate(nums):
        if x == target:
            return i
    return -1            # ← 循环里没找到，要有兜底返回
```

**坑**：函数没写 `return` 会返回 `None`，**不会报错**。所以写的时候一定要检查每条路径都有返回。

## 8. 复杂度怎么数（D5 起每天用）

| 写法 | 复杂度 |
|---|---|
| `a[i]`、`d[x]`、`len(a)` | O(1) |
| `for x in a` | O(n) |
| `x in a`（list） | O(n) |
| `x in d` / `x in s` | O(1) |
| `a.insert(0, x)`、`a.pop(0)` | O(n) |
| `sorted(a)` | O(n log n) |
| 双重 `for` | O(n²) |

**判断口诀**：有几层"跟 n 有关的循环"，就是 n 的几次方。循环里调了一次 O(n) 的函数，层数要加一层。

## 9. 本周踩坑对照表

| 症状 | 原因 | 修法 |
|---|---|---|
| `TypeError: can only concatenate str` | 字符串 + 数字 | `int()` 或 `str()` 转换 |
| `IndexError: list index out of range` | 下标超了 | 取元素前先判 `len`，或循环边界改成 `len(a)-1` |
| `KeyError` | 直接 `d[k]` 取不存在的键 | 用 `d.get(k, 默认值)` |
| `AttributeError: 'NoneType'` | 函数漏了 `return` | 检查每条分支都有返回 |
| `s = {}` 想建空集合 | `{}` 是空字典 | 用 `set()` |
| 结果和预期差 1 | `range` 右边界不含 | 记住 `range(a,b)` 是 `a..b-1` |
| 删元素时漏删 | 循环里 `remove` 导致下标移位 | 用写指针双指针法 |

## 10. 攻坚沉淀（014 专项，11/23 追加）

### 易错点 1：负下标同样「含左不含右」

`range(-1, -len(s), -1)` 走不到 `-len(s)`（第一个字符）——和正向 range 是同一套规则。**倒序完整遍历的右边界是 `-len(s) - 1`**。判断口诀：负下标 `i` 合法 ⟺ `abs(i) <= len(s)`。

### 易错点 2：变式题的用例必须按新模型重推

把「最长公共前缀」的用例搬去测「最长公共后缀」时，期望值要重新算——`"ab"` 是 `"abc"` 的前缀，但**不是后缀**（末位 c≠b，公共后缀是 `""`）。模型方向变了，照搬用例 = 用错误答案自证正确。

### 易错点 3：Python 没有 `math.abs`

`abs()` 是内置函数，直接用，不 import。`math` 模块里没有 abs。

### 易错点 4：反向遍历返回「已匹配部分」的切片公式

倒数第 m 个（负下标 i）失配时，已匹配 `|i| - 1` 个，返回 `str1[len(str1) + i + 1:]`。验证锚点：**第一位（i=-1）失配必须返回 `""`，全部匹配返回整个 str1**——两个锚点都过，切片公式才算对。

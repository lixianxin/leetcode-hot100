## 一、什么代码才可以放进来

| 标准 | 说明 |
|---|---|
| ✅ 裸写通过 | 不看笔记、不看历史提交，能独立写出并通过全部用例 |
| ✅ 自测 4 类用例 | 空 / 单元素 / 重复或极值 / 无解，都跑过 |
| ❌ 抄的题解 | 抄的放在 `WNN-复盘.md` 的「模板」字段里，不进这个文件夹 |
| ❌ 只过示例的代码 | 大概率有边界洞，属于未完成 |

**这一条要严格执行。** 这个文件夹的价值在于"每一行都是我写的"，混进抄的代码，它就变成了一个没有意义的代码堆。

## 二、文件命名

```
NNN-题目名.py
```

示例：`001-两数之和.py`、`015-三数之和.py`、`146-LRU缓存.py`

- 题号三位补零，保证 `001 < 015 < 100 < 146` 排序正确
- 题目名用中文原题名，不要翻译
- 一题多解加版本后缀：`001-两数之和-v1.py`（暴力）、`001-两数之和-v2.py`（哈希）
- **不建子文件夹**。100 个文件平铺，用 `Ctrl+P` 输题号直接跳，比点三层文件夹快

## 四、代码风格（只要求四条）

1. **类名固定 `Solution`，方法名照题目给的签名**，不改 LeetCode 的接口
2. **变量名有意义**：`left`/`right`/`slow`/`fast`/`seen`，不用 `a`、`b`、`i1`
3. **不加废话注释**，只在"为什么这么写"不显然的地方写一句
4. **不留调试代码**：`print()` 提交前删掉

```python
class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        seen = {}
        for i, x in enumerate(nums):
            need = target - x
            if need in seen:
                return [seen[need], i]
            seen[x] = i        # 先查后存：元素不能重复使用
        return []
```

## 五、commit message 规范

格式：`题号 题目名: 一句话结论`

```
001 两数之和: 哈希一次遍历 O(n)
026 删除有序数组中的重复项: 读写双指针原地去重
fix 026: 修正空数组越界
docs W01: 补 D3 语法坑记录
```

前缀约定：
- 直接写题号 → 新增题解
- `fix` → 修 bug
- `docs` → 文档变更
- `refactor` → 重写同一题的解

为什么在意这个：commit 历史就是你的成长曲线。半年后 `git log --oneline` 一拉，能看到自己在哪个专题卡了最久。
